# Ubuntu / WSL 2 setup from zero

## 1. Open the right environment

Ubuntu is installed under WSL 2 on this computer. Open **Ubuntu** from the Windows
Start menu. In Windows VS Code, install Microsoft's **WSL** extension, then open
the project through a WSL-connected window. The bottom-left indicator should
identify `WSL: Ubuntu`.

The current working copy can be opened from Ubuntu with:

```bash
cd '/mnt/c/Users/Asani/Documents/ChatGPT/IAM Fullstack Project'
code .
```

Keep using this working copy while its changes are uncommitted. After the branch
is pushed, clone into the Linux filesystem for faster dependency/build I/O:

```bash
mkdir -p ~/projects
cd ~/projects
git clone https://github.com/ray-code2/IAM-Midpoint-Integration.git iam-platform
cd iam-platform
git switch feat/phase1-foundation
code .
```

Choose one active working copy. Avoid editing the Windows and Linux clones as if
they were the same directory. Do not delete the original working copy until all
required changes are committed and visible in the new clone.

## 2. Verify prerequisites inside Ubuntu

```bash
git --version
node --version
npm --version
java -version
javac -version
docker version
docker compose version
python3 --version
```

Expected: the Node 22 patch in `.nvmrc` (at least 22.22.2 for the test dependencies),
JDK 21, and a reachable Linux Docker server.
The Maven Wrapper downloads the project's Maven version; a system Maven install
is not required. This Ubuntu distribution already had Git, Node 22, npm and JDK 21
when inspected. Windows PATH checks did not reveal those Linux tools.

If Java/basic utilities are missing:

```bash
sudo apt update
sudo apt install -y git openjdk-21-jdk curl unzip python3 ca-certificates
```

Use your approved Node version manager to select the version in `.nvmrc`.
With nvm already installed, run `nvm install` followed by `nvm use` in the repo.
Do not mix Windows node_modules with Linux node_modules; run `npm ci` in Ubuntu.

## 3. Enable Docker for Ubuntu

Start Docker Desktop on Windows. Under **Settings > Resources > WSL Integration**,
enable integration for Ubuntu and apply the change. Use Linux containers.

Reopen Ubuntu and check `command -v docker` and `docker version`. Prefer the
integrated Linux CLI rather than a Windows executable reached through `/mnt/c`.
Do not install a competing Docker daemon inside Ubuntu when using Desktop's
WSL integration.

Docker/Oracle need enough available memory and disk; allow several GB for images,
the database and builds. Development containers use synthetic data only.

## 4. Run the foundation

From the repository root:

```bash
bash scripts/check.sh
cp .env.example .env
```

Edit `.env`, assigning two different values generated by `openssl rand -hex 24` to
`ORACLE_PASSWORD` and `DB_PASSWORD`. They are local database credentials and must
not be committed. Then:

```bash
docker compose up --build --detach --wait --wait-timeout 600
bash scripts/smoke.sh
```

Visit http://localhost:8088. Run the Oracle integration test in the same local setup:

```bash
set -a
source .env
set +a
export JDBC_URL="jdbc:oracle:thin:@127.0.0.1:${ORACLE_PORT:-1521}/FREEPDB1"
export DB_USERNAME=iam_app
cd backend
bash ./mvnw --batch-mode --no-transfer-progress -Poracle-it verify
```

Only source your own locally created `.env`; it is interpreted as shell code.
The suggested random hex values are compatible with both shell and Compose syntax.
Changing password values after Oracle has initialized does not rotate the existing
database users. Restore the original local values or rotate users deliberately.

## 5. Daily workflow

```bash
git switch main
git pull --ff-only
git switch -c feat/your-small-change
# Make the change and its tests.
bash scripts/check.sh
git status --short
git diff
git add <reviewed-files>
git commit -m "feat: describe the result"
git push -u origin feat/your-small-change
```

Open a pull request to main and follow the SDLC checklist. Never paste access
tokens into remote URLs or commit credentials to solve authentication problems.
